# 문제 정의서

- 도메인: 기업 IT / BA의 현업 업무 개선 요청 접수 및 초기 요구사항 분석.
- 현재 방식: 자유 형식 이메일·대화로 요청을 받고 담당자가 수작업으로 정리한다. 빈도·처리 시간·사용 시스템·예외가 누락되면 반복 인터뷰가 발생한다.
- 개선 가설: 접수 직후 LLM으로 정보를 구조화하고 누락 질문을 생성하면 초기 분석 초안 작성 시간을 줄일 수 있다.
- 대상 사용자: 현업 요청자, IT 담당자 / BA, 프로젝트 관리자.
- 범위: 단일 분석 Agent, 입력 폼, 근거를 포함한 분석 보고서. DB·ERP 연계·멀티 Agent·자동 승인 제외.
- 성공 기준: 핵심 3사례에서 보고서 생성 성공, 60초 이내 응답 목표, 질문 10개 이하, 입력에 없는 확정 사실 0개 목표. T04~T05로 정보 부족과 불명확한 목적을 검토한다.
- 개선 효과 목표(아직 미측정): 같은 사례의 수작업 초안 작성 대비 AI 초안 작성+검토 시간 30% 감소. 사람이 각각 초 단위로 측정한다.

AS-IS: 자유 형식 요청 → 수작업 내용 정리 → 누락 정보 재질문 → 초기 검토.

TO-BE: 요청 입력 → AI 구조화 및 근거 확인 → 질문·개선 후보 초안 → 사람이 검토 → 후속 인터뷰.
