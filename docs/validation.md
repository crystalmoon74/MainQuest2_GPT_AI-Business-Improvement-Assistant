# 검증 결과 및 남은 실험

## 현재 상태

실제 Gemini 실행: 미수행. 이 작업 환경에 사용자 API Key가 제공되지 않아 모델 정확도·응답 시간·업무 개선 효과를 측정하지 않았다. 모의 API 테스트는 실제 AI 실행 실적에 포함하지 않는다. 과제의 '최소 1개 AI 모델 직접 실행' 조건은 아래 실행 후 충족 여부를 판단해야 한다.

## 자동 검증

`python -m unittest discover -s tests -v`: 필수 입력, 길이 제한, 인용 근거 제거, 질문 개수, API 응답 처리(모의), 호출 한도 안내를 확인한다. 실제 모델 품질 테스트가 아니다.

## 실제 실험 절차

1. 익명화 사례 3개 이상을 준비한다. 현재 samples는 가상 사례이므로 가능하면 본인 경험을 익명화한 실제 업무 사례로 교체한다.
2. API Key 설정 후 `python evaluate.py`를 실행한다. 가상/익명화 자료만 사용한다. 이 CLI는 명시적으로 실험 파일을 저장한다.
3. 생성된 보고서와 원문을 비교해 아래 표를 채운다.
4. 동일 사례를 빈 보고서 양식에서 수작업으로 작성한 시간과 AI 생성+사람 검토 시간을 비교한다. 단순 API 지연시간과 업무 처리시간을 구분한다.

| 사례 | 확인할 항목 | 실제 실행 | 수작업 초 | AI+검토 초 | 허위 확정 사실 수 | 피드백 |
|---|---|---|---|---|---|---|
| T01 구매 승인 | 미제공 승인 단계를 확정하지 않음 | 미수행 | 미측정 | 미측정 | 미측정 | 대기 |
| T02 엑셀 보고 | 매월·3시간을 중복 질문하지 않음 | 미수행 | 미측정 | 미측정 | 미측정 | 대기 |
| T03 Helpdesk | 접수 분산과 중복 처리 구조화 | 미수행 | 미측정 | 미측정 | 미측정 | 대기 |
| T04 정보 부족 | 미확인 표시와 추가 질문 | 미수행 | 미측정 | 미측정 | 미측정 | 대기 |
| T05 불명확한 목적 | AI 도입 자체를 효과로 확정하지 않음 | 미수행 | 미측정 | 미측정 | 미측정 | 대기 |

## 실패 및 한계

- 자동 테스트에서 입력에 없는 인용을 포함한 항목을 넣으면 제거됨을 확인한다. 의미적 환각 전체를 차단하는 검증은 아니다.
- 알려진 정보를 다른 표현으로 다시 질문하거나, 원문을 인용하면서 과장된 결론을 낼 가능성이 남는다. 실제 실패 사례는 실험 후 원문·결과·수정 방향과 함께 기록한다.
- 호출 한도·잘못된 키·모델 ID·연결 지연 시 분석이 실패할 수 있다. 앱은 오류를 알리며 사용자가 다시 실행할 수 있다.
- 효과·정확도는 아직 검증되지 않았다. 실제 사용 도입 전 BA/현업 검토가 필요하다.
