# 모델 선정 및 Agent 설계

텍스트 요청에서 정보를 추출하고 질문·보고서를 생성하는 과제이므로 텍스트 생성 LLM을 선택했다. 이미지 탐지·분할 모델은 입력/출력과 맞지 않는다.

| 후보 | 적합성 | 선택 및 제약 |
|---|---|---|
| Gemini API (기본 gemini-3.5-flash-lite) | 한국어 요청 분석, 구조화 출력 | 교육에서 익숙한 API와 Python 중심 구성. 계정별 가용 모델을 환경변수로 변경 가능 |
| GPT API | 텍스트 분석 및 구조화 출력에 적합 | 유효 후보이나 이번 MVP의 API 경로를 하나로 제한 |
| 로컬 오픈웨이트 LLM | 외부 전송 감소 가능 | 메모리·실행 환경 및 배포 부담이 있어 후속 검토 |

성능 우위나 비용 우위는 측정하지 않았다. 선정은 구현 적합성 판단이며 실험 비교 결과가 아니다.

Agent는 자율 실행 도구가 없는 단일 목적 분석 파이프라인이다. 입력 검증 → 시스템 지침과 사용자 데이터 분리 → Gemini generateContent → Pydantic 스키마 검증 → 인용 근거 확인 → 보고서 렌더링. ADK·MCP 없이 단순 API 호출을 사용하는 PRD 허용 범위를 따른다.

입력의 명령 무시를 지시하지만 프롬프트 인젝션 방어를 보장하지 않는다. 근거 문자열 포함 검사는 인용 존재만 검사하며, 해석의 타당성·질문 중복 의미·이미 제공한 정보의 재질문은 사람이 검토해야 한다.

API 참고: https://ai.google.dev/api/generate-content
